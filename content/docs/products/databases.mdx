Fabort can provision PostgreSQL, MySQL, Redis, Valkey, and MongoDB instances in a project. Valkey is wire compatible with Redis, so Redis clients and `redis://` URLs connect to it unchanged.

## Create a database

1. Open **Databases** and select **Create Database**.
2. Enter a name, region, and availability zone under **General**.
3. Choose the engine and version, then set the username or accept the generated default.
4. Let Fabort generate a secure password, or select an existing project secret.
5. Choose the machine: a platform preset, a project machine template, or a custom size (100 to 32,000 CPU millicores in steps of 50, and 128 to 131,072 MiB of memory in steps of 64). Your plan quota bounds all three.
6. Review the prefilled internal TCP endpoint. You can add, remove, or change endpoints, including public hostname or address allocation. The endpoint name is the default hostname label, and the complete hostname and availability state appear below the name while you type.
7. Set persistent storage from 1 to 1,000 GB.
8. Review and create the database.

The machine step shows what the database reserves against your plan: one database, its CPU, memory, and disk. Creation stays disabled while the plan is still loading, when provisioning is paused, or when the reservation would exceed a limit.

Names are normalized to lowercase, dash-separated identifiers up to 48 characters. Redis and Valkey default to the username `default`; other engines default to the normalized database name.

Fabort provisions the database workload, service, editable network endpoints, credentials, and Longhorn-backed persistent volume. If an older client omits endpoint configuration, Fabort creates an internal TCP endpoint on the catalog port.

## Connect

Overview displays engine, version, status, host, port, username, storage, machine, and template. A **Connect** panel lists a connection URL and the matching command line client (`psql`, `mysql`, `redis-cli`, `valkey-cli`, or `mongosh`) for the engine. The password is never shown: the commands read it from a `DB_PASSWORD` environment variable. Passwords are managed through Secrets; when a credential secret is attached, use **Open** to inspect it if your permissions allow secret-value access.

An address ending in `.svc.cluster.local` is internal to the runtime network. In that state, the frontend reports that the external endpoint is pending and the Connect panel stays empty until an endpoint with an address is active.

## Database sections

- **Overview**: status, host health, connection details, and the Connect panel, with **Start**, **Stop**, and **Restart**. Restart replaces the running pod and keeps its data; a stopped database must be started instead.
- **Logs**: the latest 500 lines from the database pods, with search and a per-pod filter. Auto refresh runs every five seconds and can be paused.
- **Metrics**: CPU, memory, network, and disk charts for a chosen time range and resolution, from the node agent's telemetry. When nothing was reported for the window the page says so instead of drawing empty charts.
- **Files**: browse and edit files in the database pod. This needs database file access permission.
- **Storage**: persistent volume status, snapshots, backups, restores, and volume expansion.
- **Network**: add, change, or remove endpoints.
- **Settings**: a description, labels, and deletion protection, plus the credential secret and the delete action.
- **Audit log**: changes to this database, such as start, stop, restart, and delete. This needs project audit read permission.

Logs and metrics require database read permission; start, stop, and restart require database update permission. Deletion protection is enforced by the API: while it is on, the database cannot be deleted from Studio or Operator until it is turned off.

## Delete a database

Delete a database from its **Settings** page or the Databases list. You are asked to confirm by typing the name. Preserve any required data first with a snapshot or backup; deleting removes the database, its data, and its endpoints.

## Not available

Fabort does not run queries for you. There is no table editor, SQL editor, trigger, policy, extension, replication, or webhook management; connect with a database client using the commands above.

The storage figures reflect the allocated volume, not measured disk utilization.
